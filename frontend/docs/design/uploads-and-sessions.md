# 上传队列、会话目录与状态同步

本页属 [Frontend 设计](../DESIGN.md)，说明首页/详情页共享的逐文件上传队列、最近会话列表及空闲同步策略。

## 逐文件串行队列（`use-file-uploads.ts`）

- 首页选文件时即校验 PDF/DOCX、20 个文件和 32 MiB 上限，首次创建会话后逐个文件调用 `POST /chat/sessions/{id}/files`，后端返回时已完成解析与索引。
- 首页与详情页共享同一串行队列，避免同会话重建索引资源竞争：等待项显示 `Queued`，处理中右侧旋转图标，成功就绪，失败行保留原因和单独重试入口。单文件失败不阻塞后续文件。
- 重复选择同名文件不重复排队，已成功文件不随提问重复上传；处理中可编辑问题但阻止发送与 Enter 提交，失败文件须重试或移除后才能提问。

## 删除、补传与自动导航

- 首页删除已处理文件调用后端删除接口，移除排队或失败文件仅清本地队列，删除失败保留原文件与提示。
- 补传仅经 Sources 中原有 `Add files`（阅读原文先关阅读器回 Sources，窄屏先切 Documents），聊天输入区不增附件入口。选文件后立即展示进度并保留历史和草稿；回答进行中、删除或恢复连接时禁止补传，空资料会话允许添加文件。详情补传变更后经 `resume` 刷新，删除刚补传文件同时清理本地就绪占位；窄屏选文件自动展开来源面板。
- 首页上传队列全部完成后自动跳转 `/tasks/{session_id}`（不要求先提问），未发问题经同页进程内草稿映射交接，不进 URL；队列未完时不导航。复制链接到其他标签页通过 `resume` 读取同一文件与历史。

## 会话目录与空闲轮询

- `workspace-list.tsx` 打开菜单时请求 `GET /chat/sessions` 读取后端数据库最近 100 条会话，聚焦或本页更新时重读并丢弃迟到响应，失败显错不回退本地缓存；不再以 `localStorage` 决定可见性，代理到同一 backend 的不同域名/浏览器共享目录。
- `session-store.ts` 只负责本页列表刷新通知与导航草稿交接；历史、资源和运行态始终来自 `/resume`。
- 空闲详情页每 5 秒及重获焦点时刷新服务端快照以同步其他标签页变动：文件选择器打开期间暂停焦点刷新与轮询，选完/取消后恢复；本页上传、删除、提问或接收回答期间停止空闲轮询。服务端快照确认成功后清理本地占位。
