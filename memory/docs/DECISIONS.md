# memory 关键决策

归属 [记忆与 Dreaming 脚本设计](DESIGN.md)，记录项目记忆与协作流程的长期取舍。

## 1. 四层按需记忆与六项程序化门禁

- 决定：保留控制面 `AGENTS.md` 与记忆面分离，活跃记忆按 L0 -> L1 -> L2 -> L3 四层按需加载，由 `memory/dream_scan.py --audit` 执行断链、预算、越层、互链墙、可达性与受保护哈希六项门禁。
- 原因：防止规则和跨会话知识随时间膨胀稀释模型注意力，避免靠人工自觉维持结构整洁。
- 排除：把所有规则与背景知识平铺进单一长 `AGENTS.md`，或取消机械化预算与断链校验。

## 2. 验收驱动开发、面向增加演进与模块级 `DECISIONS.md`（2026-11-24）

- 决定：开发流程改为以用户确认的可观察验收标准为锚点，代码实现坚持"面向增加、谨慎修改既有稳定逻辑"；对话中用户拍板的决策按三要素（做了什么决定、为什么这么选、排除了哪些备选方案）即时落盘到对应包的对应模块 `DECISIONS.md`（独立子模块自带 `docs/` 时放 `<module>/docs/DECISIONS.md`）；`memory/tasks/` 仅作施工暂存，归档进 `memory/archive/` 前必须逐条迁出长期决策并标明去向，`dreaming` 归档前二次核查。
- 原因：原微粒度 TDD 易沦为 Agent 贴近内部实现自写单测并自评通过，偏离外部需求；仅记在任务单里的决策在归档后会被新会话遗忘；将决策绑定到具体模块可促使代码与文档同步朝增量扩展演进，避免反复修改大总文档。
- 排除：维持微粒度单测先行门禁；把决策留在归档任务单不管；另建全仓单一 `DECISIONS.md` 或平行顶层 `docs/adr/`、`docs/exec-plans/` 目录。
