# 核心工程原则（Core Beliefs）

归属 [设计文档总目](index.md)，记录本仓库跨包通用的工程品味与底线。当具体任务未逐项指定实现细节时，按下列原则取舍。

## 1. 面向增加、谨慎修改与彻底清理

- 新能力、新文档格式或新扩展点优先通过新增独立模块承接，尽量减少对既有稳定逻辑的侵入式改动，同时避免无意义的提前抽象；前端单文件尽量控制在约 300 行以内，不为不可能发生的场景堆砌防御分支。
- 动手前必读目标模块 `DECISIONS.md`；当新需求与旧模块已有决策冲突时，优先新增模块或显式扩展，不静默改坏旧契约。
- 一旦确认废弃旧方案、旧接口或旧 UI，直接彻底删除，不保留向后兼容层、字段 alias 或兜底开关；上游输出异常时先查上游源码并从源头修正，禁止在下游臆测字段写兼容兜底。

## 2. 通用内核与实验隔离

- 通用文档解析与问答内核的 schema、工具定义、校验规则和系统提示词保持领域与任务无关，禁止针对单份样本或单一行业编写特化补丁与启发式例外，不隐瞒代码中的硬编码规则。
- 生产模块仅承载已验证的稳定逻辑，算法探索、对比评测和临时联调脚本统一隔离在 `.gitignore` 忽略的 `experiments/` 目录，不混入生产包或正式 `tests/`；结构解析或算法变更须在多份差异明显的真实文档上同口径验证后再落地。

## 3. 验收驱动、测外部行为与真实渲染

- 需求先整理为用户可观察的验收标准并确认再动手；优先用接口契约、集成测试、故障复现和真实端到端验证锁定结果，不以贴近内部实现的微粒度单测代替行为验收。
- 前端布局、样式与交互改动须在真实浏览器中结合渲染实看核验，不只凭单测与构建判定完成；Agent 测试锁定消息结构、工具可用性与行为契约，禁止对易变的 system prompt 写固定原文子串快照断言。
- 跨服务、并发或高风险改动在自验后增加一次独立视角的只读核查，降低自评偏差；涉及协议联调或前端交互的改动尽量做真实运行态验证，不只依赖 Fake/Mock。

## 4. 边界显式校验、单源真相与清晰所有权

- 数据进入系统边界时显式校验格式、配额与路径安全（存储桶/键白名单、资源引用归属、请求参数校验），遇到已持久化产物或索引损坏时显式报错拒绝，不静默回退全量重建。
- 每类状态与知识只保留一个权威来源：对话稳定历史以 `backend` SQLite 经 `crud.transaction()` 原子提交的 `chat_messages` 为准；前端投影以 `GET /resume` 快照为准；文档按单源维护，其他位置只留简短指针。
- 服务间通过显式协议与对象存储边界解耦，不跨服务直接 import 内部模块，不把网络 I/O 等待与会话状态写锁混在一起。

## 5. 机械门禁优于口头提醒

- 长期生效的决策必须写明三要素（做了什么决定、为什么这么选、排除了哪些备选方案）并落入对应模块 `DECISIONS.md`；凡能转成结构测试、打包测试、英文文案校验或审计脚本的不变量，优先用自动化门禁锁死。

## 6. 公开仓库定位、沟通与文档写作品味

- 仓库定位为 MIT 协议公开项目 TraceAgent，根 [README.md](../../README.md) 保持用户视角，不写毕业设计、MVP 措辞或私人草稿，且每次更新须同步日文版 [README.ja.md](../../README.ja.md)；严禁提交本机绝对路径、真实外部业务 PDF/DOCX、本地 SQLite 库、临时截图或实验产物，清理误追踪文件用新 commit 取消追踪而不改写 Git 历史。
- 默认中文沟通，新增文档、注释和 docstring 使用中文（标准英文术语除外）；表达直接平实，按事实与实现写，不用破折号、弯引号和装饰性符号，不堆砌粗体标签或规则腔套话，也不在多处反复复述同一套规矩。
- 各包偏长的设计与接口文档按"轻量总览索引页 + 同级主题子文件"维护，`README` 与 `tests/docs/` 保持单文件；设计文档中的 Mermaid 图表按职责拆分为小图（流程、正常时序、竞态时序分开），优先使用直白业务描述（如条件 UPDATE）替代堆叠黑话。
- 提交按单一逻辑变更组织，保留无关运行态目录（如 `storage/data/`）。
